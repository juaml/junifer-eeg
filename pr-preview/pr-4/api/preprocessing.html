6.3. Pre-processing¶

Provide EEG preprocessors.

pydantic model junifer_eeg.preprocess.EEGAdaptiveRejection¶

Class for the adaptive rejection of bad EEG channels and epochs.

Port of _adaptive_egi from nice-extensions. In order:

  1. Bad channels by threshold: the channels whose peak-to-peak amplitude exceeds reject in more than n_epochs_bad_ch epochs.

  2. Bad channels by variance: the channels whose variance is an outlier (iterated z-scoring with zscore_thresh and max_iter).

  3. Bad epochs by threshold: the epochs in which more than n_channels_bad_epoch of the good channels exceed reject. They are dropped.

  4. Bad channels by high frequency: the channels whose standard deviation above 25 Hz is an outlier.

The bad channels are marked as bad (info["bads"]). Then, the subject is rejected (an error is raised) if fewer than min_channels channels are good or fewer than min_epochs epochs remain.

Parameters:
rejectdict

The peak-to-peak amplitude threshold for each channel type, e.g., {"eeg": 100e-6}.

n_epochs_bad_chfloat or int, optional

The number (int) or proportion (float) of epochs exceeding the threshold for a channel to be bad (default 0.5).

n_channels_bad_epochfloat or int, optional

The number (int) or proportion (float) of good channels exceeding the threshold for an epoch to be bad (default 0.1).

zscore_threshfloat, optional

The z-score threshold for the outlier detection (default 4).

max_iterint, optional

The maximum number of iterations of the outlier detection (default 4).

min_channelsfloat or int or None, optional

The minimum number (int) or proportion (float) of good channels. If None, it is not checked (default None).

min_epochsfloat or int or None, optional

The minimum number (int) or proportion (float) of epochs remaining, out of the epochs before rejection. If None, it is not checked (default None).

pydantic model junifer_eeg.preprocess.EEGAutoReject¶

Class for repairing and rejecting bad epochs with autoreject.

The local autoreject (Jas et al. 2017) learns a peak-to-peak threshold for each channel with cross-validation. In each epoch, the channels exceeding their threshold are interpolated if they are at most n_interpolate, and the epoch is dropped if they are more than consensus of the channels (both chosen by cross-validation among the candidates). Only the good EEG channels are used. Port of the autoreject option of the icm/lg/raw/egi preprocessing of NICE.

Needs the channel positions (see EEGSetMontage).

Parameters:
n_interpolatelist of int or None, optional

The candidates for the maximum number of channels to interpolate in an epoch. If None, autoreject’s default (default None).

consensuslist of float or None, optional

The candidates for the proportion of bad channels to drop an epoch. If None, autoreject’s default (default None).

cvint, optional

The number of folds of the cross-validation (default 10).

thresh_method{“bayesian_optimization”, “random_search”}, optional

The method to find the thresholds (default “bayesian_optimization”).

seedint or None, optional

The seed of the cross-validation and the threshold search (default None).

n_jobsint, optional

The number of parallel jobs (default 1).

min_epochsfloat or int or None, optional

The minimum number (int) or proportion (float) of epochs remaining, out of the epochs before rejection. If None, it is not checked (default None).

Raises [ValidationError][pydantic_core.ValidationError] if the input data cannot be validated to form a valid model.

pydantic model junifer_eeg.preprocess.EEGDropEvents¶

Class for dropping the events (annotations) that follow other events.

Drops each of the events whose previous event, among the events and the preceded_by events, is one of the preceded_by events (e.g., the frequent trials right after a rare trial). The other annotations are ignored. With scope="block", the first event of each block (between the boundaries of the concatenated files) is never dropped.

Parameters:
eventslist of str

The events to drop.

preceded_bylist of str

The events after which the events are dropped.

scope{“block”, “recording”}, optional

Whether the previous event is searched in the block or in the whole recording (default “block”).

pydantic model junifer_eeg.preprocess.EEGFixedLengthEpochs¶

Class for cutting continuous EEG data into pseudo-epochs.

Fixed-length epochs are cut every duration plus a random jitter, starting at onset. Each epoch spans from tmin to tmin + duration around its event (both included).

Parameters:
durationfloat

The length of each epoch, in seconds.

tminfloat, optional

The start of each epoch relative to its event, in seconds (default 0.0).

onsetfloat, optional

The time of the first event, in seconds (default 0.0).

jitterlist of float or None, optional

The minimum and maximum time between the end of an epoch and the next event, in seconds. The time is drawn uniformly (in samples) for each epoch. If None, the epochs are contiguous (default None).

baselinelist of float or None, optional

The baseline interval. See mne.Epochs (default None).

seedint, optional

The seed of the random number generator for the jitter, so the epochs are the same every time (default 0).

pydantic model junifer_eeg.preprocess.EEGRenameChannels¶

Class for renaming the EEG channels.

In order: the regular expression pattern is replaced by replacement in the names that match it (e.g., EEG FP1-REF to FP1), the names in mapping are renamed, and, with montage_case, the names are written as in the montage of the EEG data type, ignoring the case (e.g., FP1 to Fp1).

Parameters:
patternstr or None, optional

The regular expression to replace (see re.sub()). If None, no replacement (default None).

replacementstr, optional

The replacement of pattern, with its groups as \1 (default "\1").

mappingdict of str and str or None, optional

The new name of some channels (default None).

montage_casebool, optional

Whether to use the case of the channel names of the montage (default False).

pydantic model junifer_eeg.preprocess.EEGRenameEvents¶

The first of the rules that applies renames the events. With scope="block", the rules are applied to each block of the recording (between the boundaries of the concatenated files), so the events of each block can be renamed differently (e.g., depending on the condition of the block).
